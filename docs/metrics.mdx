---
title: Metrics
description: Explore tokens, cost, running time and task corrections.
---

Open **Metrics** in the workspace sidebar. Tokens, Duration and Cost have separate charts that share the same local datetime range, activity selection and grouping. Token and cost bars are stacked; duration lines show each group's elapsed running time. Group by **agent type**, **harness** or **model**. Model grouping uses the model selected for each run, rather than inferring the model from native reports.

Choose **Today**, **Last 7 days**, **Last 30 days**, **Last 3 months**, **Year to date** or **Custom**. Last 3 months uses calendar months; Year to date starts at local January 1. The panel below the filters lets you select local From and To dates and times. The end is exclusive. Clicking a day or hour in any chart updates those fields and selects Custom. With a chart focused, use arrow keys to inspect intervals and Enter to select one.

Select **All activity**, **Coordinator** or an individual task. Task activity includes its Workers, subtasks, review and clarification work. Coordinator conversations remain workspace activity because a conversation can span multiple tasks.

Workspace totals use the same compact Tokens, Duration and Cost cards.

The **Tasks** table below the charts uses the same selected range. It starts with the highest token total; click Tokens, Duration or Cost to change the sort order, or click a task name to open it. Coordinator activity does not appear as a task row.

Task details show five compact cards: **Tokens**, **Duration**, **Cost**, **Corrections** and **Retries**. Hover, focus or tap Tokens, Duration or Cost for Worker and Reviewer values. Corrections counts started correction work; retries counts started Worker retries after failure or stopping. Answer continuations do not count as either. Counts come from execution records, independently of the number of results or feedback messages.

Duration measures elapsed running time, counts parallel work once and excludes idle gaps. Workspace charts and task rows clip it to the selected interval. Token charts place consumption when it was reported. Unreported values remain a dash; completed work retains its available records. Active task counters update while visible.

Cost applies versioned USD API token rates to each reported model separately, including helper models. Hover, focus or tap Cost to see its API pricing date. Every calculation retains the rates it used; a catalog update does not change earlier costs. Unknown prices, missing cache lifetimes or incomplete model attribution remain `-`, not zero. Values below one cent display `<$0.01`. Native token counters include cached input where reported; cache and reasoning subsets are not added twice. Detailed accounting, coverage and retained native observations remain available through the read-only usage API and MCP. Flowfield does not reconstruct unreported consumption.

Compatible Codex, Claude Code and Pi updates continue reporting tokens without requiring an exact release match. Flowfield validates the reported counters and session boundaries; missing or inconsistent data remains unavailable. Claude Code requires version 2.1.277 or later because older versions report resumed-session totals differently. Pi requires version 1.1.0 or later with full-session statistics; its aggregate cannot establish provider completeness. Completed assistant request reports can supply per-model pricing when they reconcile with the accepted session delta. Previously unavailable measurements are not reconstructed after an update.

The Coordinator and external MCP clients can use `get_workspace_metrics`, `get_task_metrics` and `get_metrics_evidence`. These share the browser’s filtered totals, charts and retained pricing evidence. Workspace reads default to the last seven days; task reads default to lifetime. Supply both `start` and `end` in `filters` for a different period. Execution receipts are paginated.

MCP summaries include `cost_usd` and `known_cost_usd` as exact USD strings. Nested cost records use integer nanodollars (one dollar is 1,000,000,000 nanodollars). Set `include_timeline: true` for chart buckets and series; summaries omit them by default. Execution items already provide the `source` and `source_id` needed by `get_metrics_evidence`.
