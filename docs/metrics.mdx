Open **Metrics** in the sidebar to compare activity across tasks, agent types, harnesses or models. Metrics supports Codex, Claude Code and Pi.

![Workspace Metrics with shared filters and totals](/images/metrics.png)

## Explore workspace activity

Choose a **Period**, or enter **From** and **To** in your local time and select **Apply**. Use **Activity** to select all work, the Coordinator or a task, and **Group by** to compare agent types, harnesses or models.

The charts and task table share these filters. Click a day or hour to narrow the range; use arrow keys and Enter when navigating by keyboard. Sort the Tasks table by Tokens, Cost or Duration, then open a task for its details. Bookmarks retain your selection.

Tokens and Cost use stacked bars. Duration uses separate lines because parallel work overlaps and should not be added together.

![Token and cost bars for the selected period](/images/metrics-cost.png)

## Inspect a task

Tasks show lifetime **Tokens**, **Cost**, **Duration** and **Corrections**. Hover, focus or tap a callout for details and the Worker/Reviewer breakdown. On narrow screens, scroll the row to see all four.

![Task metrics and recorded work](/images/task-metrics.png)

Corrections counts work started to address feedback, excluding retries and answer continuations.

## Understand the numbers

- **Tokens** are reported by the harness, including cached input without double-counting.
- **Cost** estimates reported input, output and cache usage at each model’s USD API rates, including helper models. Missing Codex cache detail uses the input rate. Tooltips show pricing dates; saved costs keep their rates. Values below one cent show `<$0.01`.
- **Duration** counts overlapping running time once and excludes idle gaps.

Cost totals include the usage that can be priced; their tooltip identifies incomplete coverage. Unavailable measurements show `-`.

## Investigate agent context

Ask the Coordinator to inspect an execution's context measurements. Built-in Coordinator turns, Workers and Reviewers retain numeric sizes for Flowfield prompts, tool definitions and tool results, including repeated read requests. `get_context_metrics` accepts the same `source` and `source_id` as metrics evidence.

These are UTF-8 payload bytes, not model tokens or billed usage. Completed native tool outputs are measured when the harness reports them, before Flowfield shortens activity previews. A preview-only fallback is labeled. Harness instructions, attachment contents and compaction are not attributed.

Native output can include Flowfield tool results, so do not add those measurements together. Text and structured tool-result sizes are also reported separately; whether both enter model context depends on the harness. Earlier executions have no retroactive measurements, and bounded records identify when event limits were reached. No prompt or tool-result text is stored in these measurements.
