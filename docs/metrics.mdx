Metrics brings the resources behind your work into the same workspace as its tasks and results. Open **Metrics** in the sidebar to see reported tokens, cost and elapsed running time for the Coordinator, Workers and Reviewers.

![Workspace Metrics with a selected period, activity filters and usage totals](/images/metrics.png)

## Explore workspace activity

Choose **Today**, **Last 7 days**, **Last 30 days**, **Last 3 months**, **Year to date** or **Custom**. Last 3 months uses calendar months; Year to date starts at local January 1. Use **From** and **To** for an exact local datetime range, then select **Apply**. The end is exclusive.

The Tokens, Cost and Duration charts share that range. Select **All activity**, **Coordinator** or an individual task, then group by **agent type**, **harness** or **model**. Model grouping uses the model selected for each run. Cost calculations price each model actually reported by the harness separately, including helper models.

Click a day or hour in a chart to explore that interval. The datetime fields update and Period becomes Custom. With a chart focused, use arrow keys to inspect intervals and Enter to select one. Bookmarks preserve the selected filters; a preset-only link such as `metrics?period=month` opens the current last 30 days.

Tokens and Cost use stacked bars so you can compare each group's contribution. Duration uses separate lines because parallel activity overlaps: adding its lines would overstate the time spent running.

![Token and cost bars use matching groups and the same selected period](/images/metrics-cost.png)

The **Tasks** table below the charts shows **Tokens**, **Cost** and **Duration** for the same interval. It starts with the highest token total. Click a column heading to change the sort order, or open a task to inspect its work. Coordinator conversations remain workspace activity because one conversation can span multiple tasks; they do not become a task row.

## Inspect a task

Each task has four callouts in one row: **Tokens**, **Cost**, **Duration** and **Corrections**. They cover the task's lifetime, including its Workers, subtasks, review and clarification work. On a narrow screen, scroll the row horizontally to reach all four.

![Task Metrics beside its definition and recorded work](/images/task-metrics.png)

Hover, focus or tap Tokens, Cost or Duration for the Worker and Reviewer breakdown. Cost values use the same rounding as the callouts, and its tooltip includes the API pricing date. Corrections counts work started to address review or human feedback; retries and answer continuations are excluded.

## How measurements work

**Tokens** come from the native harness. Cached input and reasoning subsets are not added twice. Charts place consumption when it was reported, and active task counters refresh while visible.

**Cost** applies versioned USD API token rates to each reported model. Every calculation retains the rates it used, so a catalog update does not change earlier costs. Values below one cent display `<$0.01`. Unknown prices, missing cache lifetimes or incomplete model attribution display `-`; they do not become zero. Historical usage collected without pricing evidence remains unavailable.

**Duration** measures elapsed running time, counts parallel work once and excludes idle gaps. Workspace charts and task rows clip it to the selected interval. Completed work retains its available records.

Compatible Codex, Claude Code and Pi updates continue reporting tokens without requiring an exact release match. Flowfield validates counters and session boundaries; missing or inconsistent data stays unavailable. Claude Code requires version 2.1.277 or later for resumed-session totals. Pi requires version 1.1.0 or later with full-session statistics; its aggregate cannot establish provider completeness. Completed assistant request reports can supply per-model pricing when they reconcile with the accepted session delta. Flowfield does not reconstruct unreported consumption.

## Ask the Coordinator or use MCP

Ask the Coordinator to compare task costs or inspect usage for a period. The Coordinator and external MCP clients use the same read-only metrics as the browser:

| Tool | Read |
| --- | --- |
| `get_workspace_metrics` | Workspace totals, task totals and grouped activity; defaults to the last seven days. |
| `get_task_metrics` | Task lifetime totals, including corrections and retry counts. |
| `get_metrics_evidence` | One execution's retained counters, accepted deltas and applied price rows. |

For example, call `get_task_metrics` with your `workspace_id` and `task_id: "T-8"`. Supply both `start` and `end` in `filters` for a bounded period. Set `include_timeline: true` to include chart buckets and series.

Summaries include `cost_usd` and `known_cost_usd` as exact USD strings. The known amount retains the priced portion when some usage is unavailable. Nested cost records use integer nanodollars: one dollar is 1,000,000,000 nanodollars. Execution items supply the `source` and `source_id` for `get_metrics_evidence`; follow its pagination cursor to inspect further receipts.
