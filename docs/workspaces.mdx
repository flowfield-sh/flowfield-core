Create a workspace for work you want to plan together: an API, its application and research files, for example. It owns the Coordinator, shared documents, tasks, Inbox and worker queue. Each project identifies an existing repository and its code-delivery destination; file and report tasks need no project.

## Create and adopt

Choose **New workspace** from Home, name it and choose a harness/model for its agents. Enable **Customize roles** for separate Coordinator, Worker and Reviewer choices. You can change each role later in workspace settings.

Open **Projects → Add project → Choose directory**, select an existing repository and review its name and ID. Registration preserves repository instructions. Before code work, establish a committed baseline and validate integration settings.

You should now see the project in the workspace's Projects view. Repeat adoption for related repositories you want to coordinate together. You can also ask a [connected agent](/mcp-integration#set-up-through-an-external-agent) to create a workspace and adopt existing repositories.

Adoption writes `.flowfield/config.toml`; commit or ignore this metadata under your repository's rules.

## Find the work

| View | Purpose |
| --- | --- |
| Task Board | Follow task state, priorities and dependencies; filter by project or label. |
| Inbox | Answer requests, review results and revisit deliveries. |
| Projects | Add repositories and reach project settings. |
| Documents | Maintain shared guidance and references. |
| Files | Browse retained outputs and their exact source results. |
| Metrics | Compare tokens, cost and running time across your work. |
| Archive | Revisit work you set aside, using Archive at the right of the Task Board filters. |

**Recent Work** shows recent requests, deliveries and active tasks. Inbox and Task Board contain the full lists.

Sidebar, Coordinator and Inbox links open work tabs. Inbox stays pinned; drag other tabs to reorder them. Use Back/Forward for history or Cmd/Ctrl-click to open a browser tab.

Tabs, filters and reading positions are saved in your browser. Unsaved answers and edits survive tab/workspace switching; leaving or reloading warns before discarding them.

Resize Work and Coordinator by dragging their shared edge. On phones, switch between **Work** and **Coordinator**.

## Plan work together

Use the Coordinator to plan across the workspace’s projects. Open a task beside the conversation to discuss its scope or priorities. See [Tasks and execution](/tasks) for board controls, dependencies and subtasks.

Edit label names, colors and usage guidance in **Settings → General → Labels**, or ask the Coordinator. It assigns useful existing labels to tasks; a task can have several. Deleting a label removes current assignments while preserving history.

## Configure at the right level

Choose agent defaults and queue capacity for the workspace. Configure setup, checks, delivery and document defaults for each project. Use task settings when a particular outcome needs different Worker or Reviewer choices.

[Configuration and permissions](/configuration) lists the settings and their scope. [Project setup and checks](/worker-setup) walks through preparing a repository for work.

## Connection recovery

If the browser loses its connection, follow [connection recovery](/troubleshooting#the-browser-loses-its-connection). Your views and drafts remain available while the service reconnects.
