Create a workspace for work you want to plan together: research files, an API, its application and its documentation, for example. It owns one Coordinator and shared work records. File and report tasks need no repository; each registered project keeps its repository and code-delivery destination.

## Create and adopt

Choose **New workspace** from Home and select its Coordinator, Worker and Reviewer settings. Inside it, open **Projects → Add project → Choose directory**, select an existing repository and review the prefilled name and ID. Tasks use workspace-local keys such as `T-1` across all projects.

The CLI uses the same registration:

`agents.json` contains `coordinator`, `worker` and `reviewer` choices, each with a `harness`, `model` and any required `effort` and `mode` returned by that harness.

```sh
flowfield workspace create "Harbor" --agents agents.json
flowfield project init /absolute/path/catalog-api --workspace WORKSPACE_ID
flowfield project init /absolute/path/reader-app --workspace WORKSPACE_ID
```

Replace `WORKSPACE_ID` with the returned workspace ID. Registration writes project identity to `.flowfield/config.toml`; it starts neither a model nor the queue. Before managed implementation, establish a committed repository baseline and [validate its integration settings](/worker-setup).

Existing registrations stay in their current workspace. Moving projects between workspaces and merging conversations are not available. Older database schemas require [starting with a fresh data directory](/storage#starting-fresh).

## Find the work

Opening a workspace takes you to **Inbox**. The sidebar provides **Projects**, **Tasks Board**, **Documents**, **Files**, **Archive** and **Settings**, plus a compact recent-work list. Tasks, requests and results open beside the persistent Coordinator. The recent-work list scrolls independently, with queue controls below it. Use the top sidebar icons for Home and Global settings, and the workspace selector to switch conversations. Drag the content pane border to resize the Coordinator.

| View | Use it to |
| --- | --- |
| Tasks Board | Follow task state and execution priorities. |
| Inbox | Answer questions, review results and resolve interventions. |
| Projects | Add repositories, view a project's tasks and reach its settings. |
| Documents | Maintain shared guidance and references. |
| Files | Browse retained task outputs and their exact source results. |
| Archive | Revisit work you set aside. |

**Recent Work** lists **Needs attention**, **Delivered**, then **In progress**. Each group keeps up to five recent items within reach. Attention and progress use recent activity; Delivered uses delivery time. Open Inbox for all requests and deliveries, or Tasks Board for all tasks. Planned tasks remain on Tasks Board, and archived tasks remain in Archive. Home shows each workspace’s actionable Inbox count.

Task cards and **In progress** links open the task itself, with its purpose and chronological feed. **Needs attention** opens the exact request; **Delivered** opens the exact result. Task badges inside requests and results open their task. Filter Tasks Board and Archive by project or label. The URL preserves filters for reload, sharing and browser history. On phones, switch between **Work** and **Coordinator**.

Links from the sidebar, Coordinator and Inbox open a work tab, or focus a tab already showing that exact view. Task settings, document revisions and collection filters remain distinct views. Links inside other work tabs navigate within that tab. Inbox stays pinned and retains its own view. Open in work tab follows the same exact-view rule. Use Back beside the title to return through that tab’s history; it is disabled at the first page. Drag tabs to reorder them, or focus a tab and press Alt+Left/Right; Inbox stays first. Selecting a tab restores its current page and reading position. Cmd/Ctrl-click opens a native browser tab. Browser Back and Forward restore the tab and page from that navigation entry. Setup and settings open beside the Coordinator.

Answers, review notes and document drafts stay bound to their original records when you switch or close resource tabs during the current browser session. Reloading or leaving the app warns about unsaved drafts. Only resource locations and layout preferences are stored in browser storage; draft contents stay in memory.

## Plan work together

Use one task for an outcome such as implementing a feature, generating screenshots or producing a PDF. Tasks can depend on other tasks across the workspace. Larger tasks may contain a local graph of subtasks, shown in its Subtasks section. The whole task owns review and delivery.

Keep durable plans in workspace documents. The Coordinator maintains task definitions, priorities and dependencies as those plans become actionable.

Labels are optional and shared across the workspace. View and edit their names, colors and usage guidance in **Settings → General → Labels**, or ask the Coordinator. Task assignments stay in the Coordinator conversation. A task can have several labels. Deleting a label removes current assignments while retaining its references in history.

## Configure at the right level

- **Workspace settings** owns the name, queue, worker defaults, shared capacity and task reviewer defaults. Task settings can override worker and reviewer choices. The Coordinator reads these defaults while planning; changing settings does not authorize starting a paused queue.
- **Project settings** owns repository identity, description, worker-document defaults and Integration: branch, setup, checks and local result previews.
- **Workspace settings → Coordinator** and the **Coordinator input** edit the same saved harness/model choice. Task **Settings → Worker** and **Reviewer** override defaults for subsequent attempts.

To open Project settings, select the project from **Projects**, then **Settings**. Its overview summarizes the directory, branch, validation, runtime and time limits; **View tasks** opens the filtered board. One project's setup blocker does not prevent ready work in other projects. See [worker setup](/worker-setup) and [workspace documents](/documents).

## Connection recovery

If Flowfield cannot reach the service, one **Connection lost** dialog pauses interaction while it reconnects automatically. Open views and drafts stay in place. Start the service again or use **Try reconnecting** to check immediately. Recovery refreshes the views; interrupted actions are never sent again automatically. Check whether an interrupted save or action completed before trying it again.

A disconnected live-update stream shows **Reconnecting…** while the service remains reachable. Individual load failures keep their local retry controls; validation errors, changed revisions and worker or reviewer recovery stay with the affected operation.
