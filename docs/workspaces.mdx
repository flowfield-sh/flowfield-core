Create a workspace for work you want to plan together: an API, its application and research files, for example. It owns the Coordinator, shared documents, tasks, Inbox and worker queue. Each project identifies an existing repository and its code-delivery destination; file and report tasks need no project.

## Create and adopt

Choose **New workspace** from Home, name it and choose a harness/model for its agents. Enable **Customize roles** for separate Coordinator, Worker and Reviewer choices. You can change each role later in workspace settings.

Open **Projects → Add project → Choose directory**, select an existing repository and review its name and ID. Registration preserves repository instructions. Before code work, establish a committed baseline and [validate integration settings](/worker-setup).

For CLI registration, `agents.json` supplies `coordinator`, `worker` and `reviewer` choices, each with `harness`, `model` and any required `effort`/`mode` returned by that harness:

```sh
flowfield workspace create "Harbor" --agents agents.json
flowfield project init /absolute/path/catalog-api --workspace WORKSPACE_ID
flowfield project init /absolute/path/reader-app --workspace WORKSPACE_ID
```

Use the returned workspace ID. Adoption writes `.flowfield/config.toml`; commit or ignore this metadata under repository rules. Existing projects cannot move between workspaces, and conversations cannot be merged.

## Find the work

| View | Purpose |
| --- | --- |
| Task Board | Follow task state, priorities and dependencies; filter by project or label. |
| Inbox | Answer requests, review results and revisit deliveries. |
| Projects | Add repositories and reach project settings. |
| Documents | Maintain shared guidance and references. |
| Files | Browse retained outputs and their exact source results. |
| [Metrics](/metrics) | Explore tokens, cost and elapsed running time by period, task, agent type, harness or model. |
| Archive | Revisit work you set aside, using Archive at the right of the Task Board filters. |

**Recent Work** shows recent requests, deliveries and active tasks. Inbox and Task Board contain the full lists.

Sidebar, Coordinator and Inbox links open work tabs. Inbox stays pinned; drag other tabs to reorder them. Use Back/Forward for history or Cmd/Ctrl-click to open a browser tab.

Tabs, filters and reading positions are saved in your browser. Unsaved answers and edits survive tab/workspace switching; leaving or reloading warns before discarding them.

Resize Work and Coordinator by dragging their shared edge. On phones, switch between **Work** and **Coordinator**.

## Plan work together

Ask the Coordinator to maintain task definitions, dependencies and labels. Drag cards within Backlog and Up next, or between them, to set priorities directly. One task owns an outcome, whether a feature, screenshot or report. Larger tasks may contain local subtasks; the whole task owns review and delivery. See [Tasks and execution](/tasks).

Edit label names, colors and usage guidance in **Settings → General → Labels**, or ask the Coordinator. It assigns useful existing labels to tasks; a task can have several. Deleting a label removes current assignments while preserving history.

## Configure at the right level

| Location | Settings |
| --- | --- |
| Workspace | Name, queue, shared capacity and Coordinator/Worker/Reviewer defaults. |
| Project | Repository identity, worker-document defaults, destination branch, setup/checks and result launcher. |
| Task | Worker and Reviewer overrides for subsequent attempts. |

The Coordinator input and **Workspace settings → Coordinator** edit the same saved choice. Run the queue separately when ready; setup blockers in one project leave ready work elsewhere eligible. See [worker setup](/worker-setup) and [document defaults](/documents#supply-worker-context).

## Connection recovery

**Connection lost** preserves views and drafts while retrying automatically. Restart the service or choose **Try reconnecting**. Interrupted actions are never replayed: check whether a save completed before retrying it.

**Reconnecting…** means the update stream is reconnecting. Other failures show their recovery action in the affected view.
