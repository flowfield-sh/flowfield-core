---
title: CLI
description: Inspect work, configure execution and automate versioned operations.
---

Most commands use the running local service. Project/task commands read `.flowfield/config.toml` in your repository; pass the command's `--project ID` option elsewhere. Workspace operations use an explicit ID. Use `--help` at any command level for its full options.

Add `--json` to data commands for structured output. Errors go to stderr with a nonzero exit status. Versioned edits require the current revision; paged reads return cursors or offsets that you must follow to read the remaining content.

## Service and storage

```sh
flowfield serve
flowfield --version
flowfield version --json
flowfield --port 8770 project list
flowfield update status
flowfield update check
flowfield storage status
flowfield storage backups
```

`serve` opens the browser in an interactive terminal; `serve --no-open` prints the URL without opening it. Global `--port` or `FLOWFIELD_PORT` selects the service; `--data-dir` or `FLOWFIELD_DATA_DIR` selects its data directory.

Update status reads the shared result or offline cache; a manual check requires the running service. These commands install nothing. Storage inspection/recovery runs offline without initializing or migrating data. See [installation](/installation#update) and [storage](/storage#inspect-and-recover).

## Workspaces and projects

```sh
flowfield workspace create "Harbor"
flowfield workspace list
flowfield workspace show WORKSPACE_ID
flowfield workspace labels WORKSPACE_ID
flowfield project init /absolute/path --workspace WORKSPACE_ID
flowfield project list
flowfield project show
```

Create a workspace before adopting a repository. `project init` accepts initial `--id`, `--name` and three-letter `--prefix` overrides; the prefix locks after the first task. See [workspaces](/workspaces) for ownership and navigation.

For optional standalone coordinator guidance, use `project guidance preview`, `install` or `show`. `project guidance export --part coordinator` prints the packaged skill offline; `remove` removes unchanged owned content while preserving local edits. See [standalone setup](/agents/overview#standalone-conversations).

## Tasks and milestones

```sh
flowfield task list
flowfield task show APP-1
flowfield task activity APP-1
flowfield task relationships APP-1
flowfield task revisions APP-1
flowfield task stages APP-1 --json
flowfield milestone list --workspace WORKSPACE_ID
flowfield milestone show M-1 --workspace WORKSPACE_ID
flowfield milestone verifications M-1 --workspace WORKSPACE_ID
flowfield milestone verification VERIFICATION_ID --workspace WORKSPACE_ID
flowfield milestone delivery M-1 --workspace WORKSPACE_ID
```

Before preparing its tasks, configure a milestone's owned branch with `milestone delivery M-1 --workspace WORKSPACE_ID --project PROJECT_ID --expected-revision REVISION`. Add `--branch BRANCH` to choose the name; the service otherwise generates one. The project's configured destination remains unchanged.

`milestone verify` prepares an upcoming staged report task with repeated `--check` values and exact milestone/task revisions. The task must depend on every delivered contribution. For [owned milestone delivery](/tasks#assemble-and-review-a-milestone), Flowfield checks the combined candidate before starting the verifier.

`milestone review VERIFICATION_ID --workspace WORKSPACE_ID --action accept --expected-revision REVISION` records human acceptance of current passing evidence. When the milestone owns a delivery branch, it also authorizes promotion of that exact verified candidate to the configured local destination. Use `--action retry_promotion` after resolving a checkout blocker, or `--action request_changes --note "Required change"` to return feedback. These actions do not push, deploy or publish a release.

Task and milestone keys accept either case; internal IDs remain exact. `task create` and `edit` accept repeated `--depends-on` keys for same-workspace prerequisites, including other projects. Repeated `--label LABEL_ID` selects labels; edits replace that set. Use `--no-labels` to clear it.

`task create --title "…"` seeds one outcome stage. `--stages-file stages.json` can supply an array of one to eight stages with `id`, `title` and `outcome`. For `task edit` or `prepare`, the file instead contains a versioned change:

```json
{
  "expected_revision": 1,
  "stages": [
    {
      "id": "implement",
      "title": "Build the import",
      "outcome": "Valid catalogs load and malformed input has useful errors"
    }
  ],
  "reason": "Scope clarified"
}
```

Read the current stages first. Task and stage changes save together; a stale revision rejects the change. The Coordinator can prepare the same agreement through its tools.

Use `task reopen APP-1 --note "Correction needed" --expected-revision REVISION` for authorized follow-up to completed work. It returns the same task to Draft/Backlog and retains delivered results and approvals. Prepare the revised task and stages before scheduling it; reopening starts no worker and grants no approval to new code.

## Execution, questions and results

```sh
flowfield workspace workers show --workspace WORKSPACE_ID
flowfield workspace workers models --workspace WORKSPACE_ID
flowfield workspace workers run --workspace WORKSPACE_ID
flowfield workspace workers pause --workspace WORKSPACE_ID
flowfield inbox list
flowfield inbox show QUESTION_ID
flowfield task runs list
flowfield task runs show ATTEMPT_ID
flowfield task results list APP-1
flowfield task results show RESULT_ID
```

Workers models returns native IDs and supported controls; `--refresh` reloads after native account/configuration changes. `workspace workers configure --help` lists the harness/model, effort, access and capacity options. Saving settings enables no queue.

Run enables eligible Up next starts. Pause leaves active work running. `task runs stop ATTEMPT_ID` targets one attempt; `task runs retry ATTEMPT_ID` queues a fresh attempt while respecting pause, dependencies and capacity.

Use `task results review --help` for approval or request-changes options. A candidate commit and current result revision are required. `task results retry-delivery --help` covers approved code blocked from the checkout. Answers and reviews preserve their task/attempt/result bindings. See [the review workflow](/tasks#review-an-exact-result).

## Project integration

```sh
flowfield project integration show
flowfield project integration configure --target main --check "make test"
```

Repeat `--check` for multiple commands; repeated `--setup` options replace the saved setup commands. Omitted setup and timeout options retain their saved values; `--clear-setup` explicitly removes setup commands. The Coordinator can configure and validate richer environment and run-command settings. See [worker setup](/worker-setup).

## Host harness settings

```sh
flowfield harness status codex
flowfield harness settings codex
flowfield harness configure codex --revision 1 \
  --executable /absolute/path/to/codex \
  --config-directory /absolute/path/to/native-config
```

Use the revision returned by settings. Configure replaces both overrides; omit both paths to restore detection. The configuration path is a directory, matching `CODEX_HOME`, `CLAUDE_CONFIG_DIR` or `PI_CODING_AGENT_DIR`. Overrides take precedence over native environment variables and change no native files or accounts.

Changes apply to future turns/attempts. A changed native session location may require the Coordinator's fresh-session recovery. For an interrupted discovery hold, inspect and stop remaining native work before confirming its exact ID:

```sh
flowfield harness confirm-stopped codex --discovery DISCOVERY_ID
```

See [agent recovery](/agents/overview#recover-setup-and-discovery). Connection commands for standalone conversations also live in [agent setup](/agents/overview#standalone-conversations).

## Saved conversation reads

`workspace coordinator-history --workspace WORKSPACE_ID --json` returns newest exchanges first; pass `next_cursor` as `--before`. Use `workspace coordinator-text TURN --workspace WORKSPACE_ID --field human --revision REVISION --json` for human text or `--field coordinator` for public replies.

Follow `next_offset` as `--offset` while keeping the revision; restart if output changed. Marked omissions are not recoverable. Saved history does not reconstruct native tool history or transfer permissions or approval.
