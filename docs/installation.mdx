title: Installation
description: Install Flowfield with uv or pip and manage its local service.

## Recommended: uv

With [uv](https://docs.astral.sh/uv/getting-started/installation/) installed:

```sh
uv tool install flowfield-core
```

uv keeps Flowfield in its own environment and exposes the `flowfield` command.
If the command is missing from PATH, run `uv tool update-shell` and open a new terminal.
The package contains the CLI, service, browser UI and agent guidance. Node and pnpm are
only needed for development. Installing the source archive uses its prebuilt artifacts.
Flowfield requires Python 3.12+ and either macOS 13+ on Apple Silicon or
glibc 2.28+ Linux on arm64/x64. Intel Macs are not supported.

## Alternative: pip

Use Python 3.12 or newer in a dedicated virtual environment:

```sh
python3 -m venv ~/.local/share/flowfield-venv
~/.local/share/flowfield-venv/bin/python -m pip install flowfield-core
```

Activate that environment to use the shorter command:

```sh
. ~/.local/share/flowfield-venv/bin/activate
```

## Set up your harnesses

Install and sign in to [Codex CLI](https://developers.openai.com/codex/cli/) or
[Claude Code](https://code.claude.com/docs/en/setup) or [Pi](https://pi.dev/docs/latest/quickstart) 1.1+ on the machine running Flowfield.
If already installed, no additional harness-support installation is needed. Flowfield
uses Codex and Pi directly and includes its official Claude SDK helper. Node/Bun is not needed.
Workers also need Git.

**Settings → Harnesses** detects the installed executables and native configuration.
Override a path only when detection needs help. **Verify installation** reads the installed version and native sign-in status (Pi checks the version only). These diagnostics send no model prompt. Accounts stay with each harness. Models load
when you open the Coordinator or workspace worker selector.
See [harness setup and recovery](/agents/overview#setup) if detection, sign-in or model access fails.

## Start and stop

```sh
flowfield serve
```

The service runs in the foreground at [localhost:8765](http://127.0.0.1:8765).
An interactive `flowfield serve` opens your browser once the service is ready.
Use `flowfield serve --no-open` to keep it closed; scripts and noninteractive sessions
only print the link. Ctrl-C stops it. Choose another port with `flowfield serve --port 8770`
and give clients the same port using `flowfield --port 8770 ...`.

Flowfield runs locally on macOS and Linux and binds to loopback. Continue with
[Getting started](/getting-started#create-a-workspace) to create a workspace and add a project.

## Update

Flowfield checks PyPI when the web app opens, hourly while the service runs, and when
you choose **Check for updates** in **Settings → Updates**. Checks run in the background and
share one saved result across browsers and the CLI. Stable installs receive stable
release notices; prerelease installs can also discover prereleases. Releases must match
your Python version and have a compatible distribution.

An available-update announcement opens **Settings → Updates**, with release notes, upgrade commands and the latest check status. Closing it leaves the update there. Failed checks preserve the last successful result; package installation is always manual.

Turn off automatic checks in **Settings → Updates**, or start the service with
`FLOWFIELD_UPDATE_CHECKS=0`. Manual checks remain available. No project content or usage
data is included in the request to PyPI.

Stop the service before upgrading:

```sh
uv tool upgrade flowfield-core
flowfield serve
```

For the pip environment:

```sh
~/.local/share/flowfield-venv/bin/python -m pip install --upgrade flowfield-core
~/.local/share/flowfield-venv/bin/flowfield serve
```

This build requires a fresh data directory for older database schemas; it does not migrate them. See [starting fresh](/storage#starting-fresh). Reopening a current-schema store retains each workspace's queue setting. Pause queues before stopping Flowfield if you want to review work before it resumes. Interrupted workers still require recovery.

Read the [release notes](https://github.com/flowfield-sh/flowfield-core/releases) and
[storage guidance](/storage) before changing builds. Restart your coding conversation
after updating installed project guidance.
