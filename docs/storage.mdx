---
title: Local storage
description: Locate your data, inspect storage and start with a fresh store.
---

One service data directory stores all your Flowfield workspaces. The default is `~/.flowfield` on macOS/Linux and `%USERPROFILE%\.flowfield` on Windows. Project repositories and installed native harness configuration remain separate.

| Location | Contents |
| --- | --- |
| `~/.flowfield/` | Database, execution artifacts and isolated task directories |
| `~/.flowfield/coordinators/` | Managed working directories for workspace Coordinators |
| `~/.flowfield/workspaces/<workspace-id>/outputs/` | Durable submitted file bytes; include these in full backups |
| `~/.flowfield/workspaces/<workspace-id>/attempts/` | Isolated working directories for repository-free tasks |
| `project/.flowfield/config.toml` | Registered project identity |
| `project/.flowfield/guidance.json` | Ownership of optional installed guidance |
| `project/.agents/skills/flowfield-coordinator/SKILL.md` | Optional guidance for standalone coordination |

Choose another data directory with `FLOWFIELD_DATA_DIR` or `flowfield --data-dir /absolute/path serve`. This changes the service's store, not an individual workspace's repository locations.

## Starting fresh

This build requires a fresh data directory when your existing database has a different schema version. It does not upgrade older databases. Stop the old service, choose a new directory and create a workspace:

```sh
flowfield --data-dir /absolute/path/to/new-flowfield-data serve
```

To reuse the default location, stop every Flowfield service and preserve the complete old directory and your repositories first. Rename the old directory to an unused backup name, such as `.flowfield-before-0.6.0` beside the original. Restart Flowfield to create a fresh `~/.flowfield` directory, then create your workspace and adopt the repositories again. If you used `FLOWFIELD_DATA_DIR` or `--data-dir`, apply these steps to that configured directory.

After verifying your backup and deciding you no longer need the old work history, you can delete the old Flowfield directory. Keep the adopted repositories, native harness configuration and credentials.

Existing repositories and native harness configuration remain separate. Startup rejects incompatible databases without modifying or deleting them. Reopening the current schema preserves saved work and queue choices; pause queues before shutdown if you want to review work before new starts resume. Interrupted workers still need recovery.

## Inspect storage

This command runs offline without creating or modifying application data:

```sh
flowfield storage status
```

Add `--json` for structured output. To inspect another store, place `--data-dir /absolute/path` before `storage`.

## Full backups

For a full backup, stop the service and copy the entire data directory together with relevant project repositories. Preserve those files together when recovering from disk loss or corruption. A backup requires a build supporting its schema; it cannot be imported into an incompatible schema. Native accounts and session data stay with their harness; back them up separately if needed for native continuation.
