title: Local storage

One service data directory stores all your Flowfield workspaces. Project repositories and installed native harness configuration remain separate.

| Location | Contents |
| --- | --- |
| `~/.flowfield/` | Database, execution artifacts and isolated task directories |
| `~/.flowfield/coordinators/` | Managed working directories for workspace Coordinators |
| `~/.flowfield/workspaces/<workspace-id>/outputs/` | Durable submitted file bytes; include these in full backups |
| `~/.flowfield/workspaces/<workspace-id>/attempts/` | Isolated working directories for repository-free tasks |
| `project/.flowfield/config.toml` | Registered project identity |
| `project/.flowfield/guidance.json` | Ownership of optional installed guidance |
| `project/.agents/skills/flowfield-coordinator/SKILL.md` | Optional guidance for standalone coordination |

Choose another data directory with `FLOWFIELD_DATA_DIR` or `flowfield --data-dir /absolute/path serve`. This changes the service's store, not an individual workspace's repository locations.

## Upgrades

Supported databases from 0.2.0 through 0.4.0 upgrade automatically. When upgrading from project-owned coordination, each project gets a separate workspace named **Project name Workspace**. Its conversation, milestones and queue settings move with it; task history, approvals, repository identity and execution ownership remain associated with the same work. New installations create no workspace until you choose to create one.

Stop the service before updating. Startup saves a verified database snapshot under the data directory's `backups/`, then runs migrations in one transaction. Failure or interruption rolls back the upgrade; errors stop startup with recovery instructions. Unsupported state is rejected without modification, and an older application cannot downgrade a newer database.

Each workspace keeps its saved queue choice. Pause queues before shutdown if you want to review work before new starts resume; interrupted workers still need recovery. Upgrades preserve project files and installed guidance. Update optional guidance separately using [agent setup](/agents/overview#standalone-conversations).

## Inspect and recover

These commands need no running service and do not initialize or migrate data:

```sh
flowfield storage status
flowfield storage backups
```

Add `--json` for structured output. To inspect another store, place `--data-dir /absolute/path` before `storage`.

A failed migration normally needs a corrected build and another start. To restore a pre-upgrade snapshot explicitly, stop the service and choose a backup ID:

```sh
flowfield storage restore BACKUP_ID --confirm
```

Recovery verifies the snapshot and saves the current database before replacement. It refuses a running service, incompatible schema, different store or writes made since the snapshot, preserving newer work. Keep the data directory at the same path when using these snapshots; restart to retry the upgrade.

## Full backups

Flowfield retains up to three database snapshots for migration recovery. They exclude execution artifacts, managed directories and repositories, and cannot repair an unreadable current database.

For a full backup, stop the service and copy the entire data directory together with relevant project repositories. Preserve those files together when recovering from disk loss or corruption. Native accounts and session data stay with their harness; back them up separately if needed for native continuation.
