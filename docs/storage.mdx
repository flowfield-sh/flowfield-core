title: Local storage
description: Locate and back up your workspace data.
---

One service data directory stores all your Flowfield workspaces. The default is `~/.flowfield` on macOS and Linux. Project repositories and installed native harness configuration remain separate.

| Location | Contents |
| --- | --- |
| `~/.flowfield/` | Database, execution artifacts and isolated task directories |
| `~/.flowfield/coordinators/` | Managed working directories for workspace Coordinators |
| `~/.flowfield/workspaces/<workspace-id>/outputs/` | Durable submitted file bytes; include these in full backups |
| `~/.flowfield/workspaces/<workspace-id>/attempts/` | Isolated working directories for repository-free tasks |
| `project/.flowfield/config.toml` | Registered project identity |
| `project/.flowfield/guidance.json` | Ownership of optional installed guidance |
| `project/.agents/skills/flowfield-coordinator/SKILL.md` | Optional guidance for standalone coordination |

Choose another data directory with `FLOWFIELD_DATA_DIR` or `flowfield --data-dir /absolute/path serve`. This changes the service's store, not an individual workspace's repository locations.

Inspection copies remain after completion or archiving. Deleting a task removes its copies and files; stop previews and save useful edits first. Adopted repositories and delivered code remain intact.

## Updating and recovery

Follow the [update commands](/installation#update). Stores from 0.6.0 onward upgrade in place.

Queues start paused unless **Auto-start worker queue** is enabled. Interrupted workers may need recovery.

### Recovery

If startup reports an unsupported database version, use a Flowfield build compatible with the reported schema. Automatic database recovery copies are stored under `backups/` in the data directory. For a manual restore, stop the service and restore the saved data directory using its matching Flowfield version.

### Stores from before 0.6.0

The task-model change in 0.6.0 did not migrate earlier stores. Keep the entire old data directory and use its matching Flowfield version to retrieve records or outputs. To start a separate workspace, choose a new, unused location with `flowfield --data-dir /absolute/path/to/new-flowfield-data serve`, then adopt your existing repositories. Repository files and native credentials stay separate.

## Inspect storage

This command runs offline without creating or modifying application data:

```sh
flowfield storage status
```

Add `--json` for structured output. To inspect another store, place `--data-dir /absolute/path` before `storage`.

## Full backups

Stop the service and copy the entire data directory and relevant project repositories. A database copy alone omits submitted files. Restore using a compatible Flowfield version. Native accounts and session data belong to each harness and need separate backups for native continuation.
