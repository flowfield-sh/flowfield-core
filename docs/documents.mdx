---
title: Workspace documents
description: Maintain shared guidance and Markdown references with revision history.
---

Open **Documents** in your workspace. **Workspace guidance** is the main document for shared purpose, conventions and references. Add custom documents for architecture, specifications or procedures. Documents belong to the workspace, independently of repository locations.

## Write and review

Open a document and choose **Edit document**. Write ordinary Markdown and use **Preview** to review it before saving. Useful main-guidance sections might include purpose, member projects, working agreements and references; choose the structure that suits your work.

Every saved change records a revision, author and time. If another edit arrives while you are writing, your draft stays intact. Copy any changes you want to keep, then choose **Load latest** and reconcile them. Unchanged saves do not create extra revisions.

Choose an entry in **Revisions** beside the document to inspect earlier content. On narrow screens, revisions appear below it. **Restore this revision** copies its title and body into a new revision, preserving intervening history. Document links keep the same identity across renames; revision links open the exact saved content.

Custom documents can be deleted with **Delete document**. Remove them from project defaults and unfinished task selections first. The document list and detail show which projects include each document in their defaults. Their revisions and prepared worker evidence remain available through existing links; restore a revision to return a document to the list. Workspace guidance stays present and can be edited or cleared.

## Work with the Coordinator

Discuss agreed guidance changes in the workspace conversation. The Coordinator can read and edit documents through its workspace tools. Each message captures the main guidance revision; opening a document beside the conversation also captures that document's saved revision. Longer content is read in bounded pages, and custom documents are retrieved when relevant.

Keep current work, questions and execution evidence in tasks. Workspace prose does not change worker settings, queue controls or approval requirements.

## Supply worker context

In **Project settings**, select **Worker documents** to choose defaults and their purpose. **Required source** means the worker must read the document; **Reference material** supplies optional supporting context. Ask the Coordinator to adjust the selection for a particular task, or pin a specific revision. Purpose belongs to the selection, so the same document can serve different roles in different tasks. Preparation fixes the selected revisions and purposes for that assignment; workspace guidance is always required.

Each worker attempt receives a bounded brief that prioritizes the current task agreement and required sources. Small required documents can appear in full; longer required documents and optional references remain available through paged reads from the frozen assignment. Workers must read required sources fully and consult references when needed. Select relevant material: linked documents and paths are not automatically copied. An assignment supports workspace guidance plus up to 20 custom documents and 1 MB of selected source text.

Editing a document or changing project defaults preserves prepared assignments and active attempts. When a selected document has a newer revision, unfinished tasks show **Newer source revision available** on the Board, in Inbox’s Waiting column and in task detail. This is information for assessing relevance; it does not block work or invalidate results automatically. The Coordinator can list affected preparations across projects with `get_document_impact`. Ask it to prepare affected upcoming work again with reviewed stages when it should adopt changes. Work already started needs reconciliation. Answer continuations preserve the original document context.

Expand **Worker documents** in a task or worker attempt to inspect its exact revisions and source size. Reported harness token usage is separate: characters and bytes measure available source text, and do not establish how much the worker read or understood.

## Adopt existing guidance

When adding an existing project, discuss its current instructions and workflow with the Coordinator. You can reference repository files from workspace guidance, incorporate agreed material into documents, or clarify how conflicting instructions should be resolved. Flowfield preserves your files and does not automatically discover or import instruction documents. Native agents may still load the repository instructions they ordinarily use.
