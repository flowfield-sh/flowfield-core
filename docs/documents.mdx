title: Workspace documents
description: Maintain shared guidance that stays current as tasks progress.

**Documents** holds versioned Markdown for purpose, conventions, architecture and specifications. **Workspace guidance** is always included in newly prepared tasks. Ask the Coordinator to create custom documents; you can edit them directly. Keep current work status in tasks and repository conventions in their authoritative files.

## Write and review

Choose **Edit**, write Markdown, use **Preview**, then save. Each changed save records a revision, author and time. **View document** returns to saved content while retaining your draft. If another edit arrives, preserve your changes, choose **Load latest** and reconcile them; stale saves cannot overwrite newer content.

Revisions show who made the change: **You**, **Coordinator**, **Worker**, **Reviewer**, **Flowfield**, or **Other** for older unrecognized identities.

![A workspace document and its revision history beside the Coordinator](/images/documents.png)

Choose a **Revisions** entry to read earlier content. **Restore** copies it into a new revision, preserving intervening history. Document links survive renames; revision links open exact saved content.

Ask the Coordinator to delete a custom document after removing it from defaults and unfinished task selections. Existing evidence links retain its history; restoring a revision returns it to the list. Workspace guidance can be cleared but not deleted.

## Supply worker context

**Saving a custom document does not select it for workers.** Choose **Edit → Use this document** to select where it applies:

| Selection | Applies to |
| --- | --- |
| Projects | Unfinished tasks in the selected projects; also editable in **Project settings → Worker documents**. |
| Include for tasks without a project | Unfinished workspace-only work such as research, screenshots or PDFs. Off by default. |
| Task-specific selection | One outcome; ask the Coordinator to select the document. |

Choose **Required source** for rules the worker must read fully, or **Reference material** for optional supporting context. The same document can have different purposes in different projects/tasks. Main workspace guidance is always required. Unchecking a default removes it from the next guidance review, unless a task explicitly selects it.

Use defaults for shared rules and task selections for specific context. Task selections can override a default’s purpose; omitting a document from that list does not exclude an inherited default. Split long mixed guidance into focused documents while preserving applicable rules and exceptions.

Preparation selects the latest revisions of workspace guidance plus at most 20 custom documents and 1 MB of text. Workers receive a brief and access to those exact revisions; linked documents must be selected separately. Task definitions describe the intended outcome; source bindings track document IDs and revisions separately. Attempt evidence preserves the sources used for that attempt. Results list their reviewed sources under **Details → Guidance**, with links to exact revisions.

## Keep tasks current

Before work starts or continues, Flowfield checks selected guidance against current revisions, defaults and purposes. If anything changed, a Reviewer compares it with the task and retained work, updates the definition, criteria or existing subtask instructions where needed, and continues automatically. Genuine conflicts or missing decisions become questions in Inbox.

Flowfield repeats this check after work and while a result awaits approval. Implementation or dependency changes return to the worker. When retained work already satisfies the updated definition, Flowfield reuses it in a new result with fresh validation, assessment and approval. The task feed shows the definition and guidance changes together, with word diffs for text. Earlier results keep their original definition, guidance and approval history. Reviews respect the queue and share worker capacity, including when independent result assessment is disabled. A configured reviewer is required.

Running attempts keep their original assignment until the next handoff. Each review uses one saved snapshot; further edits are checked before its conclusion applies. Completed tasks retain their delivered guidance without automatic reopening.

## Work with the Coordinator

Each message captures the main guidance revision and any saved document open beside the conversation. The Coordinator can read and maintain these documents through the same revision checks.

During adoption, agree which repository instructions to reference or incorporate. Existing files stay in place, and native harnesses may still load their own instructions. Configure queue, models and permissions in settings.
