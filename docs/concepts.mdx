Flowfield is a workspace for you and your coding agents. Shape the plan in one conversation, give workers the context they need, and keep review and delivery attached to the outcome.

## People and agents

| Role | Responsibility |
| --- | --- |
| You | Define what matters, prioritize work, answer questions and approve exact code results. |
| Coordinator | Explore ideas, maintain shared context, organize tasks and help review outcomes. |
| Workers | Complete assigned tasks in isolated directories or repository checkouts. |
| Reviewer | Assess the whole task result, request corrections and surface decisions needing you. |
| Service | Schedule eligible work, retain execution evidence and deliver authorized results. |

The Coordinator can keep planning while workers run. Browser, CLI and agent tools share the same work.

## Workspaces, projects and tasks

A [workspace](/workspaces) brings related projects together around one Coordinator, shared documents, labels, Task Board and Inbox. Each project identifies an existing repository and its integration settings.

A task defines an outcome and success criteria. Code tasks belong to a project; file and report tasks can belong to the workspace. Tasks can depend on other tasks or split into local subtasks that share one review and delivery.

[Documents](/documents) preserve shared guidance and references with revision history. Flowfield checks selected guidance before work and review, while each attempt and result retains its exact sources. Labels classify tasks without changing their execution or approval.

## The board and queue

The board shows **Backlog → Up next → In progress → In review → Done**. Automatic implementation and assessment remain In progress; In review means a human decision or approved delivery is pending. An Up next task may still need setup or clarification. The shared queue starts eligible work when dependencies and capacity allow it.

[Tasks and execution](/tasks) covers scheduling and local subtasks. [Inbox](/inbox) separates decisions in Needs me, completed outcomes in Delivered and earlier responses in History. Notifications point back to the relevant item.

## Agent settings and permissions

Choose Codex, Claude Code or Pi independently for the Coordinator, Workers and Reviewer. Workspace worker/reviewer defaults apply unless a task overrides them; running attempts retain their captured choices. Project settings own setup, checks and the delivery branch. See [agent setup](/agents/overview) and [worker configuration](/worker-setup).

Native tool permissions govern agent actions on the service host. A tool permission decision is separate from human approval to deliver worker code.

## Results and approval

A result contains the outcome, files and verification evidence. The Reviewer assesses it before code comes to you for approval. Flowfield delivers approved code to the local repository; complete files and reports finish after review. See [review and delivery](/review) and [Files](/files).

Running, pushing and publishing need separate instructions. Each repository has its own results and approvals.
