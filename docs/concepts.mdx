Flowfield is a workspace behind your coding conversation. You and the Coordinator shape the problem and keep the plan current; workers implement bounded tasks while the service tracks execution and delivers approved results.

## People and agents

| Role | Responsibility |
| --- | --- |
| You | Define what matters, prioritize work, answer questions and approve exact code results. |
| Coordinator | Explore ideas, maintain shared context, organize tasks and help review outcomes. |
| Workers | Implement their assigned tasks in isolated repository checkouts. |
| Service | Schedule eligible work, retain execution evidence and deliver authorized results. |

The Coordinator can keep planning while workers run. Browser, CLI and Flowfield tools act on the same records; opening a task or inspecting code starts no worker and grants no approval.

## Workspaces, projects, tasks and milestones

A [workspace](/workspaces) brings related projects together around one Coordinator, shared documents, milestones, labels, Board and Inbox. Each project identifies an existing repository and its integration settings.

A task belongs to one project and describes an outcome and success criteria. A milestone groups tasks across projects. Only tasks form dependencies, including across projects in the same workspace; each task still executes and delivers in its own repository.

[Documents](/documents) preserve shared guidance and references with revision history. Selected revisions become part of a prepared worker assignment. Labels classify tasks without changing their execution or approval.

## The board and queue

The board shows **Backlog → Up next → In progress → In review → Done**. Priority, readiness and human attention are separate: an Up next task may still need setup or clarification. The workspace's shared queue starts eligible work when dependencies and worker capacity allow it.

[Tasks, Inbox and review](/tasks) covers scheduling, questions, feedback and recovery. Inbox is the single place to find work needing your attention; notifications point back to it.

## Agent settings and permissions

The Coordinator has its own harness/model choice. Workspace worker defaults apply to tasks unless a task overrides them. Project settings own setup, checks and the delivery branch. See [agent setup](/agents/overview) and [worker configuration](/worker-setup).

Native tool permissions govern agent actions on the service host. A tool permission decision is separate from human approval to deliver worker code.

## Results and approval

A result records an outcome and its verification evidence. Approval identifies the exact candidate and destination; a changed candidate needs another review. Flowfield validates and delivers approved code while preserving conflicting local changes. A report-only task can finish without code approval when its agreed outcome is complete.
