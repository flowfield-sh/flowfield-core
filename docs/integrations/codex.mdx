Install the [Codex CLI](https://developers.openai.com/codex/cli/) and sign in.
Make sure `codex` is available in the terminal where you start Flowfield.

**Settings → Harnesses → Check saved setup** reads native version and sign-in status
without sending a model prompt. **Not checked** means this diagnostic has not run;
it does not block a working conversation or mean you are signed out.

## Coordinator

The [Coordinator](/coordinator) and workers use your installed `codex app-server` directly.
Choose your model, effort and access mode beside the chat input; models load automatically. Flowfield uses Local automatically; worker delivery configuration can wait.
The service supplies a scoped MCP connection per turn; you do not need to register the standalone connection below for built-in chat.

Managed tool approvals offer native one-time allow/deny choices. Requests for broader
permission profiles or persistent grants are denied; choose an appropriate native
access mode in model settings.

## Standalone conversation

Use the [shared connection steps](/integrations/overview#standalone-conversations)
with `codex`. The same connect, status and disconnect commands work for either harness.
Start a fresh Codex conversation in the adopted project and ask it to read your board.

## Configure workers

Native Codex must be installed and authenticated on the machine running Flowfield.

Follow [Worker setup and checks](/worker-setup) to configure and validate delivery.
In **Workers**, select a model, reasoning effort and access mode from the connected harness.
Project defaults can be overridden for individual tasks.

Each attempt uses the service host's tools and credentials in a separate checkout, with its
own temporary and output directories. Setup commands install your project's dependencies.
Use `FLOWFIELD_WORKSPACE` and `FLOWFIELD_RUNTIME_DIR` in reusable setup scripts. Keep databases,
ports and other shared resources separate, or serialize work with one worker slot.

Checks use the service's Local environment. Saved inspection launchers use the terminal's
host environment plus the inspection copy's paths; credentials are never written into them.
Tool permission requests appear in the task and **Needs you**. Result delivery requires
explicit approval. Worktrees separate file edits; shared services, ports and databases
still need their own isolation.

If the service cannot find Codex, restart it from a terminal with the correct PATH, then use
**Refresh models**, or set an executable override in **Settings → Harnesses**.
