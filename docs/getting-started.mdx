Flowfield keeps your planning conversation, shared context and agent work together. Start with one existing repository, then add related projects when you need them.

![A Flowfield workspace with its Coordinator and shared board](/images/board-overview.png)

## Install and start

[Install Flowfield](/installation) and sign in to [Codex, Claude Code or Pi](/agents/overview#setup) on the same machine. With uv:

```sh
uv tool install flowfield-core
flowfield serve
```

Keep the service terminal open while using Flowfield. It opens the local browser interface; Ctrl-C stops the service.

## Create a workspace

Choose **New workspace**, enter a name and choose **Create workspace**. Home and the sidebar list your workspaces. Each has one Coordinator, shared work views and its own worker queue.

## Add your project

Open **Projects → Add project → Choose directory**. Select an existing repository, review its name, ID and three-letter task prefix, then choose **Add project**. The folder chooser operates on the machine running Flowfield; use the [CLI](/cli#workspaces-and-projects) if it is unavailable.

Discuss the repository's existing instructions and roadmap with the Coordinator. Decide what should stay in repository files and what belongs in [workspace documents](/documents). Adding a project preserves those files and leaves the queue paused in a new workspace.

See [Workspaces and projects](/workspaces) when coordinating several repositories.

## Shape the first task

Choose the Coordinator's harness and model beside its input, save, and describe the problem. For example:

> People get stuck importing their first catalog. Read the existing code and instructions, help me narrow the scope, and prepare a small task with clear success criteria.

Work through assumptions and tradeoffs before queuing implementation. Edit documents directly; use the Coordinator to maintain milestones and tasks. Open a task beside the conversation to discuss its definition or a particular result.

Before running workers, ask the Coordinator to configure the project's delivery branch, setup commands and checks, then validate setup. Choose a worker harness and model in **Workspace settings → Workers**. [Worker setup and checks](/worker-setup) explains configuration and local result previews.

## Run the task

Move the prepared task to **Up next** and choose **Run queue**. Its status explains any missing setup, input or prerequisite. Eligible work runs in an isolated checkout; open the task to follow activity.

Questions and reviews appear in **Inbox**. A saved worker answer continues managed work when the queue permits it. **Pause queue** prevents new starts while active workers continue; **Stop worker** stops one attempt.

## Review the result

Read the worker's report and project checks. Inspect **Code changes**, or use **Try result** to test an independent copy. Request changes when needed. When the exact result is ready, choose **Approve and integrate** and confirm, or explicitly approve that result in the Coordinator conversation.

Flowfield delivers approved code to the configured checkout before marking the task **Done**. If local changes block delivery, follow the recovery action without discarding your work. See [Tasks, Inbox and review](/tasks) for dependencies, feedback and recovery.
