For your first task, ask Flowfield to improve the local-development instructions in a repository you know. You'll define the outcome with the Coordinator, run a Worker, review the change and deliver it to your local branch.

## Before you begin

Have these ready:

- [Flowfield installed](/installation) and running with `flowfield serve`.
- A supported [coding agent installed and signed in](/agents/overview).
- An existing Git repository with a README and a committed starting point.

Choose a project whose setup commands you can recognize and whose README you can review. The example below uses your repository's own tools.

<span id="install-and-start" />

## Create a workspace

Choose **New workspace**, name it after your project, and select a harness and model for its agents. Choose **Create workspace**.

You'll see the Coordinator conversation beside the workspace views. The worker queue starts paused, giving you time to prepare the task.

## Add your project

Open **Projects → Add project → Choose directory**. Select your repository, review its name and ID, then choose **Add project**.

Send this to the Coordinator, replacing the branch name if needed:

> Help me prepare this project for its first task. Read its existing instructions and scripts. Use main as the delivery branch, configure the setup and validation commands appropriate to this repository, agree on a run command or why no runnable preview applies, and validate the setup. Explain anything you need me to decide.

The project should show successful setup validation before you start work. You can inspect the commands in **Project settings**. [Project setup and checks](/worker-setup) explains those settings.

## Shape the first task

Ask the Coordinator:

> Create a task to improve the README's local-development instructions. A new contributor should be able to find the prerequisites, install dependencies, run the tests and start the application using the repository's existing commands. Verify the instructions against the project scripts. Keep the change focused on the README and preserve useful existing content.

Open the task on **Task Board**. Read its definition and success criteria beside the conversation. For this task, check that it calls for accurate prerequisites, working commands and a clear order of steps.

Discuss any adjustments with the Coordinator or edit the task while it is in **Backlog**. You're ready to proceed when you know how you'll judge the result.

## Run the task

Move the task to **Up next** on the board, then choose **Run queue** in the sidebar. Open the task to follow its activity as a Worker reads the project and makes the change.

If the agent needs a decision, open **Inbox → Needs me**, read the question and send your answer. Work continues with that answer attached to the task.

The Reviewer then checks the proposed README against the assignment and evidence. It can send the work back for corrections before presenting a result to you.

## Review the result

Open the result from Inbox. Read the report and reviewer findings, then inspect **Code changes**. Check the README as a new contributor would: are the prerequisites clear, are the commands correct, and can you follow them in order?

![A result with its report, checks and approval controls](/images/result-overview.png)

If something is missing, choose **Request changes** and describe it. For example:

> The test command is clear, but the setup instructions omit the environment file used by the application. Add the existing example-file step and explain which values a contributor needs to supply.

When the result meets the criteria, choose **Approve and integrate** and confirm. Flowfield delivers the approved change to your local branch and marks the task **Done**.

## Return to the outcome

Open the README in your repository to see the delivered change. You can revisit the result in **Inbox → Delivered** or open the task to read its questions, checks and earlier results.

For your next task, try a small bug fix or feature. [Planning effective tasks](/planning-tasks) covers scope and context; [How Flowfield works](/concepts) explains how tasks, agents and results fit together.
