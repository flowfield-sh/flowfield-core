Shape your project with the [Coordinator](/coordinator) and a visual task board. Let
workers build, then use their results to refine the plan. This guide takes an existing
project from its first conversation to a reviewed task.

![Flowfield board with tasks, priorities and work ready for review](/images/board-overview.png)

## Install and start

Install and sign in to [Codex CLI](https://developers.openai.com/codex/cli/). Then install Flowfield with [uv](https://docs.astral.sh/uv/getting-started/installation/):

```sh
uv tool install flowfield-core
flowfield serve
```

Flowfield uses installed Codex or Claude Code directly. No separate integration install
is needed. Configure nonstandard paths in **Settings → Harnesses**. Published 0.2.1
predates this update; Claude currently requires a development build.

Choose **Settings → Appearance** for System, Light or Dark theme. This preference stays
in your browser and applies across projects.

## Add your project

Choose **Add project** in the sidebar, then **Choose directory**. The native folder chooser
opens on the machine running Flowfield. Select your existing project directory, then review
the prefilled **Name**, **Project ID** and **Task prefix** below it. All three are required and
editable. Choose a unique ID and three-letter prefix if another project already uses them.
Under **Agents**, choose a Coordinator and worker harness, model and supported controls.
You can also set parallel worker capacity. These choices are optional and remain editable
in Project settings. Review the guidance option, then click **Add project** to save everything;
the worker queue starts paused.

You can also register the same project from another terminal in its directory:

```sh
flowfield project init
```

Keep **Install project guidance** selected to add the coordinator skill and its `AGENTS.md`
reference while preserving existing instructions. If skipped,
install later under **Project settings → Coordinator**. Commit the instructions so workers
receive them in their checkouts.

Registration saves the project identity in `.flowfield/config.toml`. Use the CLI if a
desktop folder chooser is unavailable.

## Start planning

If you skipped the Coordinator choice during setup, choose a ready harness beside the input in the [Coordinator](/coordinator), wait for models to load,
then choose its model and supported effort/access controls and save. Native startup hooks
can run during discovery; it sends no model prompt. Describe what you want to achieve. For example:

> Help me add CSV export to this project. Review the existing code and suggest a small first task before starting implementation.

The Coordinator works in the selected project and is ready to plan without repository
guidance. Worker setup can wait until you are ready to run tasks. For a standalone Codex
conversation, follow [standalone coordinator setup](/integrations/codex#connect-a-standalone-coordinator).

## Prepare the first task

Ask your coordinator to configure the destination branch, dependency setup and checks,
then validate setup. Add a run command if you want to try results locally. Choose a worker
harness and model, with effort and access mode where supported. Models load automatically when you open the selector. You can also edit these under the project’s
settings icon; see [Worker setup and checks](/worker-setup) for the fields and an example.

Project **Workers** settings supply defaults for model, effort and access. Individual
tasks can override them; changes apply to the next attempt. See [Concepts](/concepts#agent-settings-and-permissions) for the worker environment.

Describe one small change and its success criteria. Ask the coordinator to capture and
prepare the task in Flowfield. Open its feed to read the agreed definition. The coordinator
maintains task intent; you control priorities and review.

## Run the task

Move the task to **Up next** and click **Run queue**. Ready tasks run when their
dependencies, setup and input requirements are satisfied. The task moves to **In progress**;
its feed shows worker activity and any questions.

Answer questions in the task feed or **Needs you**. Your saved answer lets the service
continue managed work when the queue permits it. **Pause queue** prevents new starts;
active workers continue. **Stop worker** stops the selected attempt.

**Retry worker** returns stopped or failed work to **Up next**. It starts when the queue is
running and a worker slot is available. The queue status shows occupancy, such as **1/2 active**.

## Review and finish

When the task reaches **In review**, read its result and checks. Inspect the diff or use
**Try result** to test an independent copy of that exact version. Request changes, or
choose **Approve and integrate**, optionally add testing notes or an approval comment,
then confirm. Approval stays tied to that selected result; changed results require a new review.

![A task feed beside the Coordinator, with a result ready for review](/images/overview.png)

Open **Code changes** to inspect the exact candidate before approving it.

![Code review beside the coordinator conversation](/images/code-review.png)

Flowfield delivers approved code to your configured project checkout, then marks the task
**Done**. Local edits that prevent delivery remain intact and the result explains the next
action. A complete report-only task can finish without code approval.

To run independent tasks together, set **Maximum parallel workers** to **2** under
**Workers**. Dependent tasks wait until prerequisite work is complete and its code is available.
