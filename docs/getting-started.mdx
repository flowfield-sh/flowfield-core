title: Getting started
description: Create a workspace, shape a useful first task, and review its result.

Flowfield keeps the plan, context, agent work and reviewed results together. Plan with the Coordinator, let workers carry out focused tasks, and decide which exact code to deliver. Start with one existing repository, then add related projects when you need them.

For reports, datasets or other files, start with a workspace and skip repository setup. Ask the Coordinator to prepare a file task with clear success criteria. [File delivery](/files) uses the same queue and independent review.

![A Flowfield workspace with labeled tasks across its shared board](/images/task-board.png)

## Install and start

[Install Flowfield](/installation) and sign in to [Codex, Claude Code or Pi](/agents/overview#setup) on the same machine. With uv:

```sh
uv tool install flowfield-core
flowfield serve
```

Keep the service terminal open while using Flowfield. It opens the local browser interface; Ctrl-C stops the service.

## Create a workspace

Choose **New workspace**, enter a name, choose one harness/model for its agents (or **Customize roles** to choose each separately), then choose **Create workspace**. Home and the sidebar list your workspaces. Each has one Coordinator, shared work views and its own worker queue.

## Add your project

Open **Projects → Add project → Choose directory**. Select an existing repository, review its name and ID, then choose **Add project**. The folder chooser operates on the machine running Flowfield; use the [CLI](/cli#workspaces-and-projects) if it is unavailable.

Discuss the repository's existing instructions and roadmap with the Coordinator. Decide what should stay in repository files and what belongs in [workspace documents](/documents). Adding a project preserves those files and leaves the queue paused in a new workspace.

See [Workspaces and projects](/workspaces) when coordinating several repositories.

## Shape the first task

Describe the problem to the Coordinator. The model you selected at workspace creation is ready in its input controls. For example:

> People get stuck importing their first catalog. Read the existing code and instructions, help me narrow the scope, and prepare a small task with clear success criteria.

Work through assumptions and tradeoffs before queuing implementation. Edit documents directly; use the Coordinator to maintain tasks. Open a task beside the conversation to discuss its definition or a particular result.

Before running code tasks, ask the Coordinator to configure the project's delivery branch, setup commands, checks and a useful Run command, then validate setup. Workspace settings retain your Worker and Reviewer choices. [Worker setup and checks](/worker-setup) explains configuration and local result previews.

## Run the task

Ask the Coordinator to place the prepared task in **Up next**, then choose **Run queue** in the sidebar. Its status explains any missing setup, input or prerequisite. Eligible work runs in an isolated checkout; open the task to follow activity.

Questions and decisions appear in **Inbox → Needs me**. Click a row to open its exact request and send an answer. A saved worker answer continues managed work when the queue permits it. **Pause queue** prevents new starts while active work continues; ask the Coordinator to stop a specific worker or review when needed.

## Review the result

The configured Reviewer assesses the whole task and can request corrections before handing code back to you. Read the result, reviewer findings, checks and limitations. Inspect **Code changes**, or copy the **Run result** command into your terminal to try an independent copy. Opening the result prepares that copy; it does not start the application.

Choose **Request changes** for another pass. When the exact code is ready, choose **Approve and integrate** and confirm, or explicitly approve that result in the Coordinator conversation. Flowfield delivers it to the configured local branch and checkout before marking the task **Done**. If local changes block delivery, follow the recovery action without discarding your work.

## Return to the outcome

Open **Inbox → Delivered** to revisit completed work. Complete reports and files finish after the configured review without a code-approval step; their outputs remain in **Files**. The task feed retains questions, answers, corrections and earlier results. See [Results, review and delivery](/review) for exact approval and recovery.
