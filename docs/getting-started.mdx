Plan with the Coordinator, let workers carry out focused tasks, and review the results. Start with an existing repository, or skip project setup for reports and files.

![A Flowfield workspace with labeled tasks across its shared board](/images/task-board.png)

## Install and start

[Install Flowfield](/installation) and sign in to [Codex, Claude Code or Pi](/agents/overview#setup) on the same machine. With uv:

```sh
uv tool install flowfield-core
flowfield serve
```

Keep the service terminal open while using Flowfield. It opens the local browser interface; Ctrl-C stops the service.

## Create a workspace

Choose **New workspace**, enter a name, choose one harness/model for its agents (or **Customize roles** to choose each separately), then choose **Create workspace**. Home and the sidebar list your workspaces. Each has one Coordinator, shared work views and its own worker queue.

## Add your project

Open **Projects → Add project → Choose directory**. Select an existing repository, review its name and ID, then choose **Add project**. The folder chooser operates on the machine running Flowfield; use the [CLI](/cli#workspaces-and-projects) if it is unavailable.

Discuss existing instructions with the Coordinator and decide what belongs in [workspace documents](/documents). New workspaces start with the queue paused.

See [Workspaces and projects](/workspaces) when coordinating several repositories.

## Shape the first task

Describe the problem to the Coordinator. The model you selected at workspace creation is ready in its input controls. For example:

> People get stuck importing their first catalog. Read the existing code and instructions, help me narrow the scope, and prepare a small task with clear success criteria.

Work through assumptions and tradeoffs before queuing implementation. Edit documents directly; use the Coordinator to define tasks and the board to order them. Open a task beside the conversation to discuss its definition or a particular result.

Before running code tasks, ask the Coordinator to configure the project's delivery branch, setup commands, checks and a useful Run command, then validate setup. Workspace settings retain your Worker and Reviewer choices. [Worker setup and checks](/worker-setup) explains configuration and local result previews.

## Run the task

Move the task to **Up next**, directly on Task Board or through the Coordinator, then choose **Run queue** in the sidebar. Its status explains any missing setup, input or prerequisite. Eligible work runs in an isolated checkout; open the task to follow activity.

Questions and decisions appear in **Inbox → Needs me**. Open a request and send your answer to continue work. **Pause queue** prevents new starts; **Stop task** in the task header stops active execution.

## Review the result

The Reviewer checks the result and can request corrections. Read its findings, inspect **Code changes**, and use the **Run result** command to try an independent copy.

Choose **Request changes** for another pass, or **Approve and integrate** and confirm. You can also approve the exact result in the Coordinator conversation. Flowfield delivers approved code to your local branch and marks the task **Done**.

## Return to the outcome

Revisit completed work in **Inbox → Delivered** and submitted files in **Files**. The task feed keeps earlier questions, corrections and results. See [review and delivery](/review) for more.
