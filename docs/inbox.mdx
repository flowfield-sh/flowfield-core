**Inbox** stays pinned beside the Coordinator as you move between work tabs. Use **Needs me** for decisions, **Delivered** for completed outcomes and **History** for earlier responses. Tasks Board tracks the execution plan; Inbox brings you the actions that need a person.

![A question and a code result in Needs me, beside the Coordinator](/images/inbox.png)

## Needs me, Delivered and History

Inbox has three tabs: **Needs me** for human decisions, **Delivered** for completed outcomes, and **History** for past responses, including answers awaiting Coordinator follow-up. Its badge counts actionable requests. Each request identifies its source, explains the decision and offers the relevant response controls directly in Inbox. Expand evidence or follow the source link when you need more context. Resource links from Inbox open a separate work tab; Inbox keeps its selected view.

**Delivered** lists completed tasks by delivery time, with their outcome, saved files or code destination. Opening a result leaves it in the list. Recent delivered tasks also appear in the sidebar; select a Delivered entry to open its exact result. Archived tasks remain available in **Archive**.

Resolved requests disappear from **Needs me** as you respond. Drafts on other requests stay in place, including on pages you have already loaded. Failed saves keep your input; if another session resolves a request while you are writing, discard your retained draft when you are ready.

| Item | Next action |
| --- | --- |
| Question | Read the context, choose a suggested answer or write your own, then send it. Worker answers continue managed work when eligible; planning answers need the Coordinator to resume and reconcile them. |
| Result | Read the selected result and destination, optionally try or inspect it, then request changes or approve and integrate it. |
| Intervention | Inspect the failure or blocker and follow its recovery action. |
| Tool permission | Allow or deny the native request while its turn is waiting. This grants no code-delivery approval. |

Suggested answers fill the composer; selecting one does not send it. Responses stay bound to the question or result you were reviewing. If that request changes while you are typing, your draft is preserved and cannot silently approve or answer its replacement.

Saved worker answers need no separate human apply step. Once assigned to a continuation, the answer remains in history; send a correction as new input rather than replacing it. Answering or retrying never enables a paused queue. Open the exact request or result from the task feed to respond, or ask the Coordinator to help sort Inbox and follow up. **Needs me** contains only unresolved requests. Once resolved, an item moves to compact **History**; if you still have an unsent response, it remains bound to that record in History until you discard it. Approved results with blocked delivery remain actionable as recovery requests.

## Open the exact request

Every question, permission request and intervention has a stable **Request** link. Use **Open in work tab** to read it beside the Coordinator. The task badge opens its purpose and history. Results have their own exact links and [review controls](/review).

Inbox stays pinned while linked resources open in work tabs. Drafts remain bound to the original request when you switch or close tabs in the same session. Reloading or leaving warns about unsaved input. A newer result or request never silently replaces the one you were answering.

## Notifications

Optional in-app and system notifications link to the item. Configure them in **Global settings → Notifications**. System notifications require browser permission and an open Flowfield page. Dismissing an alert answers no question and approves no result.
