Ask the Coordinator for the files you need and how they should be checked. A workspace task can produce a report, image, dataset or binary without registering a repository. Project tasks can submit files alongside their code results.

![Retained task files with an image preview and a link to their source result](/images/files.png)

## Browse and use results

Open **Files** from the sidebar or select a filename in a result. Filter by task, sort by name, date or type, and browse folders with breadcrumbs. Select a file to preview it. The URL preserves your view for bookmarks and navigation.

Use **Source** to open the result that submitted a file, **Open** for browser-supported formats, or **Download** for the original. Images, CSV, UTF-8 text, Markdown and code preview inline. HTML and SVG display as source.

| Preview | Limit |
| --- | --- |
| Text, Markdown and code | 64 KiB, with a truncation notice. |
| CSV | 200 data rows and 50 columns; first row supplies headings. Formulas remain text; malformed CSV falls back to source. |

Complete file/report tasks finish after review. Request changes from the result or discuss missing input with the Coordinator.

## Inputs and later versions

The Coordinator can supply message attachments or submitted files as task inputs. Workers receive copies, including files from delivered prerequisites. Later versions leave existing inputs unchanged.

Subtasks’ files are combined in the final result. Earlier versions remain available after corrections.

## Worker and coordinator tools

Create repository-free work with `create_task(workspace_id=…, task=…)`, omitting `project_id`, and prepare it with `completion="report"`. Built-in Coordinator tools already bind the workspace. Subsequent task tools use the same `workspace_id` and task key. Select immutable file IDs with `task.input_files`.

Workers write final files in the supplied `output_directory`, also available as `FLOWFIELD_OUTPUT_DIR`, and include relative paths and optional descriptions in `submit_result.files`. Only explicitly submitted files are retained. A submission supports up to 32 regular files, 128 MiB per file and 512 MiB total. Symlinks, hardlinks and paths outside the output directory are rejected. Finish writing files before submitting; a failed capture leaves the result unsubmitted so the worker can correct it.

Use `list_workspace_files` for bounded browsing, optionally filtered by task key. `get_workspace_file` returns metadata and a verified local path. Inputs are limited to 32 explicitly selected files; with prerequisite and predecessor files, an attempt can receive up to 256 files and 512 MiB. Combined task outputs are bounded to 256 files and 512 MiB.

## Retention and backup

Files survive archiving, attempt cleanup and restarts. [Deleting a task](/tasks#archive-or-delete) removes its outputs unless other tasks still reference them.

See [local storage](/storage#full-backups) to preserve metadata and file bytes together. Missing or changed files retain their metadata and show a problem; restore the original bytes to recover them.
