Ask the Coordinator for the files you need and how they should be checked. A workspace task can produce a report, image, dataset or binary without registering a repository. Project tasks can submit files alongside their code results.

![Retained task files with an image preview and a link to their source result](/images/files.png)

## Browse and use results

Open **Files** in the workspace sidebar. Choose a task on the left, browse folders in the center, and inspect the selected file on the right. Task keys show their full title in a tooltip and are ordered by their most recent output. Breadcrumbs and **Up** return to parent folders. Sort by name, newest or type, and select a file to see its name, size, submission time and producing task. Use **Load more files** for the next page, including in **All files**. A task correction can submit a replacement with the same filename; the earlier file remains separately selectable by its timestamp.

Choose **Open** for browser-supported PDF, text and image files, or **Download** to save a copy. Other types download. Active HTML and SVG content downloads rather than running inside Flowfield. Compact file links also appear in task results.

Folders follow the submitted file paths. Images, CSV tables, UTF-8 text, Markdown and source code preview both here and alongside the task result. Code uses syntax highlighting; HTML and SVG display as source without executing. Text previews show up to 64 KiB, with a truncation notice for larger files. CSV tables use the first row as column headings and show up to 200 data rows and 50 columns. Formulas remain literal text; malformed CSV falls back to its source. Long text fills the available inspector height, while short previews stay compact. Download the file to read the complete original.

Complete file/report tasks finish after their files are retained and any configured task reviewer signs off. Reviewers can request corrections or ask a focused question about missing input. When task review is disabled, incomplete results offer **Request follow-up** to send specific instructions to the worker. Completion records delivery; it does not endorse the report's conclusions.

## Inputs and later versions

The Coordinator can select sent message attachments or previously submitted files as task inputs. Workers receive separate copies of those exact bytes. Delivered prerequisite files are also supplied automatically. Later edits or successor results cannot silently replace the inputs of an existing attempt. Reopening a completed task preserves its previous files and result history.

For decomposed work, the final task result contains its contributions’ retained files. The task reviewer checks the combined outcome. Earlier file versions remain accessible after corrections.

## Worker and coordinator tools

Create repository-free work with `create_task(workspace_id=…, task=…)`, omitting `project_id`, and prepare it with `completion="report"`. Built-in Coordinator tools already bind the workspace. Subsequent task tools use the same `workspace_id` and task key. Select immutable file IDs with `task.input_files`.

Workers write final files in the supplied `output_directory`, also available as `FLOWFIELD_OUTPUT_DIR`, and include relative paths and optional descriptions in `submit_result.files`. Only explicitly submitted files are retained. A submission supports up to 32 regular files, 128 MiB per file and 512 MiB total. Symlinks, hardlinks and paths outside the output directory are rejected. Finish writing files before submitting; a failed capture leaves the result unsubmitted so the worker can correct it.

Use `list_workspace_files` for bounded browsing, optionally filtered by task key. `get_workspace_file` returns metadata and a verified local path. Inputs are limited to 32 explicitly selected files; with prerequisite and predecessor files, an attempt can receive up to 256 files and 512 MiB. Combined task outputs are bounded to 256 files and 512 MiB.

## Retention and backup

Submitted bytes live under `<data-root>/workspaces/<workspace-id>/outputs/`, separately from disposable attempt directories. Files survive task archiving, attempt cleanup and service restart. New versions have new identities; no automatic output deletion is performed.

Back up the entire service data directory to retain both metadata and files. A database copy alone does not contain the file bytes. If a retained file is missing or changed, Flowfield preserves its metadata and reports the problem; restore the original bytes from backup. See [local storage](/storage#full-backups).
