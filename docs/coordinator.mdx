---
title: Working with the Coordinator
description: Explore the problem, maintain the plan and review work in one conversation.
---

Use one conversation across your projects to explore ideas, organize tasks and review outcomes. Start with the problem you want to solve; the Coordinator can investigate it with you before shaping implementation work. [Planning effective tasks](/planning-tasks) gives examples of useful requests and success criteria.

## Start a conversation

Open your workspace and send a message. Change the harness, model or supported effort/access controls beside the input when needed. Enter sends; Shift+Enter or Command/Ctrl+Enter adds a new line. Worker defaults are configured separately.

The Coordinator uses tools and credentials on the machine running Flowfield, within its selected access mode. Its Flowfield tools are scoped to the workspace.

Ask it to configure project setup, organize tasks, or run, push or publish a result. Specify the destination and checks when requesting delivery beyond your local branch.

## Use the work beside the chat

Open a task, document or filtered board beside the same conversation. Each message captures the selected task, result, document revision or board filters when sent. The Coordinator asks when the intended project is ambiguous.

Ask it to explain blockers, update guidance, adjust priorities or review a result. Explicit approval of an exact code result here records the same decision as the browser controls.

## Attach context

Use the paperclip, drag files onto the input or paste an image. Remove unsent attachments with ×. Sent files remain with the message and can be downloaded.

Attach up to four text/code files of 64 KiB each or PNG, JPEG and WebP images of 2 MiB each. Image input depends on the selected harness.

Ask the Coordinator to record lasting decisions in workspace documents. See [Workspace documents](/documents) for shared guidance and task context. Reattach files when starting a fresh session or sending them to a separate task attempt.

## Controls and commands

Model, effort, access and Fast choices apply to subsequent messages. Fast offers quicker responses with increased usage on supported models. The context ring shows current occupancy.

Type `/` to load available commands, select one and send. Commands take no arguments or attachments:

| Command | Effect |
| --- | --- |
| `/status` | Show native model/settings or context status. |
| `/compact` | Compact the native conversation; this may use the model. |
| `/mcp` | Show native MCP connections. |
| `/skills` | List available skills. |

See [Agent setup](/agents/overview) for supported controls and harness-specific behavior. Answer tool permission requests in the conversation or Inbox while the turn is waiting.

## Stop and continue later

One Coordinator turn runs per workspace, independently of worker slots. Replies and tool activity stream as it works; you can draft your next message while it runs. **Stop** ends that turn, preserving saved work changes. Task workers continue independently.

Finished turns show the final reply with expandable activity. Open events for commands and file changes, or **Retained output** for longer details. Earlier messages load on demand.

Switching harness, adding a project or changing its repository path starts a fresh native session. Saved conversation remains available.

If a session cannot resume, restore its native history or choose **Start new session**, then resend your message with any needed attachments.

If cleanup is uncertain, stop remaining native work on the host, then choose **Confirm coordinator stopped**.
