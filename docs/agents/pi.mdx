## Setup

Install [Pi](https://pi.dev/docs/latest/quickstart) 1.1 or newer and configure a provider on the machine running Flowfield. Flowfield uses the installed `pi` command directly.

In **Settings → Harnesses**, keep detected paths or override the executable and configuration directory. Accounts stay in Pi. See [shared setup](/agents/overview).

## Models and access

Models and thinking levels come from Pi’s provider configuration. Manage provider sign-in in Pi.

If no models appear, configure a provider in Pi on the service host, then choose **Retry loading models** in Flowfield.

Pi tools use **Full access**, without built-in per-tool approvals or a sandbox. Flowfield still requires exact approval before delivering worker code.

## Commands

The Coordinator supports `/compact`, `/status`, `/mcp` and `/skills`. Use Pi’s terminal for terminal-only commands.

## Sessions and Stop

Unchanged settings resume the Coordinator session. Stop aborts execution and closes the session, including extension shutdown hooks.

See [Coordinator recovery](/coordinator#stop-and-continue-later) for saved history, fresh sessions and uncertain cleanup.

## Native customization

Pi loads native extensions, tools and MCP settings alongside Flowfield. Extension confirmations appear in Flowfield; widgets and free-text dialogs require Pi’s terminal.

## Standalone conversation

Use the [shared connection steps](/mcp) with `pi`:

```sh
flowfield integration connect pi
```
